# Fix S1: secret keys in the code or in git

1. Move the value to `.env.local` (or the hosting dashboard's Environment Variables) and read it with `process.env.NAME` on the server only. No hard-coded fallback: fail at startup if it's missing.
2. Add to `.gitignore`: `.env`, `.env.*`, and keep `!.env.example` with empty values.
3. Stop tracking: `git rm --cached .env`.
4. **Rotate the key** in the provider dashboard (only the owner can). Once a key was in git or a deploy, treat it as public; deleting it from the code is not enough, it stays in git history.
